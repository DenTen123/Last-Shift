# Метеостанция Люк-30 (Last Shift)

Выживание в бункере-метеостанции на 30 дней: добываем ресурсы, принимаем людей,
чиним генератор и поломки, а в конце собираем машину и уезжаем со всеми живыми.
Godot 4.7, код на GDScript, сцена собирается из кода.

## Как устроен код

Вся логика игры — в двух автозагрузках: `game.gd` (состояние и правила) и
`snd.gd` (звук). Сцена — `BunkerWorld` (world.gd): при запуске он сам собирает
мир из модулей-компонентов. Модули почти не знают друг о друге — они слушают
сигналы `Game` и вызывают его методы.

```
  АВТОЗАГРУЗКИ                    СЦЕНА main.tscn -> BunkerWorld (world.gd)
  +------------+                  +----------------------------------+
  | Game       | <-- вызовы -----| BunkerWorld собирает модули:     |
  | (game.gd)  | --- сигналы --> |  PlayerController (герой)        |
  | Snd (snd.gd)                  |  StaffController (сотрудники)    |
  +------------+                  |  StationController (станции)     |
        ^                         |  GateController (ворота, люк)    |
        | звук                    |  IncidentController (поломки)    |
  +------------+                  |  WeatherSystem (свет, погода)    |
  | UI (ui.gd) | -- окна, меню -> |  PathNavigator (пути A*)         |
  | HUD, тосты |                  |  RestRoom, BunkerBuilder,        |
  +------------+                  |  SceneLayout, Camera, Editor     |
                                  +----------------------------------+
```

Что делает каждый модуль:

- **Game** — всё состояние: время, ресурсы, сотрудники, вылазки, поломки,
  генератор, гости у ворот, сохранения. На каждое изменение даёт сигнал `changed`.
- **UI** — HUD (время и полоски) и все окна; рисует состояние из Game и передаёт
  нажатия кнопок обратно в Game.
- **PlayerController** — герой: ходьба за курсором, кнопка E, выбор предметов.
- **StaffController** — 3D-персонажи сотрудников и гостей, их прогулки и сон.
- **StationController** — станции: грядка, кухня, печь, измельчитель, кушетка, шкаф.
- **GateController** — ворота со смотровым окном, люк, выезд машины (победа).
- **IncidentController** — маркеры поломок (течь, замыкание, дверь).
- **WeatherSystem** — освещение по времени суток, осадки, затемнение при поломке.
- **PathNavigator** — пути по сетке A*, препятствия.
- **RestRoom** — койки и сон сотрудников.
- **SceneLayout + LayoutStore** — раскладка мебели, хранится в bunker_layout.json.
- **BunkerBuilder, CameraController, LocationEditor** — мебель, камера, редактор (F).

## Центральный цикл на примере вылазки

```
  окно экспедиции (пульт люка или клавиша 5)
        |
        |  проверки: генератор цел? дверь не заклинило?
        +-- нет --> сообщение о причине, состояние не меняется
        |  да
  отметить сотрудников галочками (sendable: жив, дома, не болен, есть силы)
        |
  выбрать место на карте и снаряжение
        |
  "Отправить отмеченных" -> Game.send() для каждого:
  списывает выносливость, away = {когда вернётся, риск, место}
        |
        v
  тик игры: 10 игровых минут в секунду, _step двигает время и таймеры
        |
  время возвращения пришло?
        +-- погода стала опасной --> сотрудник не вернулся
        +-- добра -> _loot(): веса места * профессия * музыка * похлёбка
        |
        v
  ресурсы и опыт, запись в журнал, сигнал worker_back ->
  StaffController ведёт персонажа обратно, UI показывает добычу
```

Ветвления: погода на выходе и к возвращению, риск травмы (погода + место +
утепление + профессия), шанс заболеть (фильтр, отвар), тайники, уровни.
Ни одна ветка не ломает состояние: недопустимые действия отсекаются до
изменения данных (проверки `sendable`, `can`, валидация файлов).

## Данные

Настройки и сохранения живут в отдельных файлах, код их только читает и пишет.

`data/game_data.json` — расширяемые данные (структура):

```json
{
  "sites": {
    "<id>": {"name": "строка", "risk": 0.14, "yield": 1.15,
              "desc": "строка", "loot": {"metal": 2.0}}
  },
  "recipes": {
    "<id>": {"name": "строка", "cost": {"potato": 2}, "min": 40,
              "buff": "loot|immune|stamina", "desc": "строка"}
  }
}
```

Заполненный пример (реальный кусок файла):

```json
{
  "sites": {
    "garage": {
      "name": "Автосервис",
      "risk": 0.14,
      "yield": 1.15,
      "desc": "детали для машины: резина, металл и топливо",
      "loot": {"rubber": 2.5, "metal": 2.0, "fuel": 1.5, "steel": 0.5}
    }
  },
  "recipes": {
    "tea": {
      "name": "Травяной отвар",
      "cost": {"herbs": 2},
      "min": 20,
      "buff": "immune",
      "desc": "24 ч никто не заболеет после вылазки"
    }
  }
}
```

Остальные файлы (в `user://`):

- `save.json` — сохранение: время, ресурсы, постройки, сотрудники (каждый со
  своим hp/выносливостью/loяльностью), открытые места, поломки, журнал.
- `record.json` — рекорд: `{"day": 12, "time": "14:30", "workers": 6}`.
- `graphics.json` — `{"scale": 1.0, "msaa": 2, "shadows": true, "effects": true, "fullscreen": false}`.
- `settings.json` — `{"volume": 0.7, "muted": false}`.
- `bunker_layout.json` — раскладка мебели и пресеты света.

## Как добавить новое место вылазки (без изменения кода)

Открыть `data/game_data.json` и добавить запись в `"sites"` с новым `"id"`.

Было (6 мест):

```json
"sites": {
  "waste":     {"name": "Пустошь", "risk": 0.0, "yield": 1.0, "loot": {"metal": 3.0}},
  "gas":       {"name": "АЗС у трассы", "risk": 0.08, "yield": 1.1, "loot": {"fuel": 3.5}},
  "warehouse": {"name": "Склад стройматериалов", "risk": 0.10, "yield": 1.15, "loot": {"metal": 3.5}},
  "pharmacy":  {"name": "Аптека", "risk": 0.12, "yield": 1.1, "loot": {"medkit": 0.5, "herbs": 2.5}},
  "mall":      {"name": "Торговый центр", "risk": 0.16, "yield": 1.2, "loot": {"food": 3.5}},
  "grid":      {"name": "Подстанция", "risk": 0.18, "yield": 1.25, "loot": {"chips": 1.5}}
}
```

Стало (добавлен «Автосервис», остальное не тронуто):

```json
"garage": {
  "name": "Автосервис",
  "risk": 0.14,
  "yield": 1.15,
  "desc": "детали для машины: резина, металл и топливо",
  "loot": {"rubber": 2.5, "metal": 2.0, "fuel": 1.5, "steel": 0.5}
}
```

После запуска место само появится на карте вылазок, в списке разведки и в окне
экспедиции, добыча будет считаться по его весам. Скриншот результата —
`docs/screenshot_new_site.png` (карточка «Автосервис · риск +14% · добыча ×1.1»).
Рецепты добавляются так же, в секцию `"recipes"` (эффект — один из
`loot/immune/stamina`).

## Что будет, если данные битые

`Game.load_game_data()` не падает:

- файла нет или он не читается — работает на встроенных значениях;
- внутри не JSON-объект — предупреждение и встроенные значения;
- у места нет имени, риск отрицательный, добыча пустая или с неизвестным
  ресурсом — запись пропускается, остальные работают;
- у рецепта пустая стоимость или неизвестный эффект — тоже пропускается.

То же с сейвами: старые сохранения без новых полей читаются через значения
по умолчанию. Проверяется автотестом `tests/smoke.gd` — он же бэкапит файлы
в `user://` перед проверками и возвращает их после.

Запуск теста: `godot --headless --path . --script res://tests/smoke.gd`
